# 0.2 Feature 2：Separate-Mesh local-shard migration

状态：本地实现与 CPU 验证完成；真实 4×L20 / 128 节点待验收
范围：只做本地 DCP 分片的跨 DeviceMesh 搬运，不做 Live Handoff

## 用户场景

source 训练任务的 DCP shard 分散在多台机器的本地盘。source 与 target 没有
共享 checkpoint 目录；target 的 world size 或 DeviceMesh 不同。用户希望生成
target 可直接加载的 DCP，同时保证 source 只读、失败不误报成功。

## 输入与输出

输入是一份带 source/target mesh 的 `MigrationSpec`：

```yaml
source:
  mesh: {shape: [2, 2], placements: [Shard(0), Shard(1)]}
target:
  mesh: {shape: [3], placements: [Shard(0)]}
```

输出是 target rank 本地可加载的 DCP，以及 plan/report/proof。target 不需要
先看到完整的 source checkpoint 目录。

## 必须保持的约束

- source 只读；source 文件 SHA256 前后一致；
- 不创建全局 raw checkpoint，不做 full gather；
- plan 显式携带 source/target mesh 和 placements；
- target staging、fsync、atomic commit、journal 续跑保持现有语义；
- 任一 target rank 失败，不得报告整体成功；
- 第一版承诺 1D/2D 的普通 Shard/Replicate 变化；复杂 TP/PP 不承诺。

## metadata owner

source 的 `.metadata` 很小，但它描述所有 rank，不能要求每台 source 节点都有
共享目录。CRD 的 `source.metadataOwnerRank` 指定唯一 owner：

1. controller 从 owner agent 读取 `GET /v1/metadata`；
2. controller 通过 `POST /v1/metadata` 把 bytes 分发给每个唯一 source agent；
3. peer agent 在本地 state dir 以 SHA256 内容寻址缓存 `.metadata`；
4. 所有 `inventory.metadata_hash` 必须与 owner 一致，否则 preparation 失败；
5. shard 数据仍由各 agent 从自己的本地 checkpoint root 读取。

这条路径不传输任何 shard 字节，也不要求 NFS/S3。若所有节点本来就共享
metadata 路径，可以继续直接读取，传输步骤是兼容的额外能力。
单次 metadata transfer 上限为 32 MiB；超过上限会 fail closed。
旧版 agent 不提供该端点时，controller 会回退到原有共享 metadata 路径；
两种路径都仍要求所有 inventory metadata hash 一致。

## 入口

本地 checkpoint：

```bash
shardferry migrate \
  --checkpoint /local/source.dcp \
  --source-mesh-shape 2,2 \
  --source-placements Shard(0),Shard(1) \
  --target-world 3 \
  --target-mesh-shape 3 \
  --target-placements Shard(0) \
  --output /local/target.dcp
```

集群：

```bash
shardferryctl preflight -f migration.yaml
shardferryctl migrate -f migration.yaml --wait
```

controller 解析 `agentSelector` / `metadataOwnerRank`，target rank 在本地
finalize 成 DCP；`--load-smoke` 可附加 rank-local load smoke。

## 已验证证据

- Python + torch 2.14.1+cpu：真实 DCP `2×2 → 3`，bitwise target、target load
  通过，source digest 不变；
- 两个独立 source agent：owner 有 `.metadata`，peer 没有；metadata transfer
  后 peer inventory 成功并完成跨 mesh apply；
- 128 source / 2D mesh → 64 target / 2D mesh 的 control-plane plan 通过；
- CLI 2D source → 1D target 通过；
- Python `291 passed / 4 skipped`；Go test/vet/build、Helm lint/template 通过。

## 明确不改

- 不改 Kueue adapter / StateGate；
- 不实现 target Job 的 N 步训练 readiness；
- 不实现 CUDA context / 进程内存热迁移；
- 不承诺任意 TP/PP 重排或未保存的 dataloader/RNG/scheduler 状态。

## 仍需真机验收

- 4×L20 上 `4→3` / `4→2` 的真实 distributed target load；
- 128 source rank、真实 selector 和大 checkpoint 的 metadata-owner 端到端；
- 物理 source/target 分离网络下的 metadata transfer 延迟和失败注入。

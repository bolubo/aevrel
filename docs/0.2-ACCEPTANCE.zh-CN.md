# shardferry 0.2 目标与验收标准

状态：设计草案
方向：Kubernetes-native checkpoint mobility operator

0.2 只覆盖 DCP 这个垂直场景；跨控制域品类和后续 provider 见
[迁移品类](CATEGORY.zh-CN.md)。这份验收标准不因为品类叙事扩大而扩大。

跨集群 gateway 的可用性验收单独记录在
[跨集群示例](../examples/cross-cluster/README.zh-CN.md)；在它跑通前，不能把
“单集群 selector 可用”当成“用户跨集群可用”。

## 1. 0.2 的目标

一句话：

> 让平台工程师安装一次 shardferry 后，可以用一份简短的
> `CheckpointMigration` 完成 128 卡 local-disk checkpoint 到 64 卡拓扑的迁移，
> 最终得到目标训练任务可加载的 DCP，并有完整的失败恢复和校验证据。

0.2 不试图解决所有 AI Infra 问题，只把一条 local-disk Kubernetes 黄金路径打穿。

## 2. 用户故事

### 主故事

一个平台工程师管理 8 个节点、128 个训练 rank：

- 每个节点有自己的 NVMe；
- source DCP shard 分散在节点本地；
- source 训练任务已经结束；
- 目标任务使用 64 个 rank；
- 没有全局 checkpoint 目录。

用户希望：

1. 不写 128 条 rankMap；
2. 不改 source checkpoint；
3. 不先把所有 shard 复制到 S3/NFS；
4. 知道 source/target agent 是否 ready；
5. 失败后可以重跑；
6. 最终 target 任务能 load。

### 目标用户体验

平台侧一次安装后，用户流程是：

```bash
shardferryctl preflight -f migration.yaml
shardferryctl migrate -f migration.yaml --wait
shardferryctl describe migration job42-128-to-64
```

用户不需要理解：

- agent endpoint；
- rankMap；
- plan node；
- journal；
- controller 内部 task 状态。

## 3. 0.2 范围

### 包含

- Kubernetes controller + source/target agents；
- `agentSelector` 自动发现；
- source agent `/v1/ranks` 本机 rank 发现；
- `shardferryctl preflight` 真实发现；
- target per-rank DCP finalize；
- rank-local DCP load smoke；
- target 任务可通过本地 target root load；
- 失败重试、resume、commit-incomplete repair；
- Helm 安装、token、mTLS 可选；
- status、events、report、基础 metrics。

### 不包含

- 训练任务自动发现和自动触发迁移；
- 在线 cutover/CDP 的生产承诺；
- 多集群跨公网调度；
- 非 DCP checkpoint 格式；
- 任意存储后端；
- 多租户隔离和完整 RBAC 产品化。

自动监听训练任务放到 0.3；0.2 先把 operator 的迁移、校验和恢复闭环做稳。

## 4. 架构目标

```text
CheckpointMigration
        |
   shardferry controller
   /                   \
source agents        target agents
local checkpoint     local target root
        \                 /
         direct range transfer
                 |
       staging -> bitwise verify
                 |
       all-rank commit barrier
                 |
       per-rank DCP finalize
                 |
       rank-local DCP load smoke
```

不变量：

1. source 只读；
2. 不创建全局 raw checkpoint；
3. 任何 rank 未验证不得 commit；
4. 任何单 rank 失败不得报告整体成功；
5. target DCP 未生成前不得报告成功；
6. target DCP load smoke 失败必须进入 `commit-incomplete`。

## 5. P0 验收标准

以下全部是 0.2 发布门槛，缺一项不能发布。

### A. 安装与发现

- [ ] 在一套干净的 kind 或小集群中，使用 Helm 安装 controller、source agent、target agent。
- [ ] controller RBAC 能 list Pods；agents 使用 9443/9444，可同节点共存。
- [ ] source 的 `.metadata` 在所有 source 节点可见。
- [ ] target 的 `/targets` 是持久 hostPath。
- [ ] `shardferryctl preflight` 能发现 128/128 source ranks 和 64 target ranks。
- [ ] selector 无匹配、source rank 缺失、重复 rank 时提前失败，不创建 target。

### B. 小规模 Kubernetes 迁移

- [ ] 16 source ranks → 8 target ranks 完整成功。
- [ ] source 文件和 SHA256 前后不变。
- [ ] 8/8 target ranks committed。
- [ ] 每个 target rank 有 `.metadata` 和 `*.distcp`。
- [ ] target rank 本地 DCP load smoke 通过。
- [ ] report、planRef、verification 可读取。

### C. 128→64 规模

- [ ] 128 source ranks → 64 target ranks，CPU/合成数据路径通过。
- [ ] 至少 1GiB 数据；有条件和环境时补 10GiB。
- [ ] plan 不产生 full gather。
- [ ] 每 target rank 的 DCP finalize 和 load smoke 通过。
- [ ] 记录每 rank bytes、总时间、峰值内存。

### D. 失败与恢复

- [ ] source agent 未启动：preflight 明确失败，target 不产生。
- [ ] source rank 缺失或 checksum 变化：迁移失败，source 不变。
- [ ] target agent 在 staging 中被杀：重启后 resume，不重复已完成 rank。
- [ ] controller 在 transfer/commit 中重启：从 CR、artifact、task 状态恢复。
- [ ] target commit 中途失败：进入 `commit-incomplete`，只能 repair，不能普通 retry 重传。
- [ ] 取消只能发生在 commit intent 前；commit 后取消必须拒绝。

### E. 产品输出

- [ ] `--wait` 显示 phase、prepared/staged/committed/failed 计数。
- [ ] 失败显示具体 rank、phase、error code 和 retryable。
- [ ] `--json` 输出稳定对象，不混入人类进度文本。
- [ ] `docs` 中明确哪些能力已验证、哪些是实验性。

## 6. P1 验收标准

这些不阻塞 0.2 Alpha，但应在 0.2 周期完成或明确进入 0.3：

- 训练任务生命周期集成（自动创建迁移）；
- S3/PVC artifact store 的完整生命周期；
- 多集群 endpoint 和凭证；
- 真实 GPU/FSDP target load；
- 大规模节点回收和 spot 恢复；
- online CDP/cutover。

## 7. 验证矩阵

| 层级 | 验证内容 | 环境 |
|---|---|---|
| 单元 | planner、agent state、resolver、DCP finalize | CPU |
| 契约 | CRD、task/report/spec schema | CPU |
| 本地集成 | 真实 DCP 4→3、target load | CPU + torch |
| K8s 小规模 | 16→8 selector | kind/小集群 |
| K8s 规模 | 128→64 selector | CPU 多节点或仿真 |
| 故障 | agent/controller/commit 故障 | kind/小集群 |
| GPU | FSDP model/optimizer load | GPU |

## 8. 发布定义

0.2 发布必须满足：

1. P0 全部通过；
2. CI 绿；
3. Release 说明列出已验证和未验证项；
4. 不把未验证的 online cutover 写成生产能力；
5. 有一个可复现的 kind/小集群 runbook；
6. 产生一个 `v0.2.0` tag 和 release notes。

## 9. 衡量成功的指标

- 一次迁移需要用户手写的 YAML 行数；
- 从 preflight 到第一个 target rank 开始传输的时间；
- 失败后恢复到继续迁移的时间；
- source bytes 被传输 / 计划 bytes；
- target load smoke 成功率；
- 128→64 的总 wall time、RSS、重试次数。

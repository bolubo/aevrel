# Contributor Ladder

The ladder describes increasing responsibility, not seniority. Promotions are
based on observed work and are always optional.

## User

- Uses shardferry, reports bugs, asks questions, and proposes use cases.
- No permission is required to participate in issues.

## Contributor

- Has at least one merged change or one substantial docs/test contribution.
- Follows the Code of Conduct and safety rules.
- Can be assigned issues and asked to review narrow changes in their area.

## Triager

- Has repeatedly produced useful reproductions, labels, or scope analysis.
- Can apply issue labels and help route reports.
- Is invited by a maintainer; no time-based entitlement.

## Reviewer

- Has demonstrated expertise in one or more areas, such as the control plane,
  DCP/data plane, Kubernetes, Python, Go, or docs.
- Has provided several substantive reviews that improved correctness or safety.
- Can be requested as a reviewer but does not have merge authority.

## Maintainer

- Has a sustained track record of merged changes, reviews, and sound judgment.
- Understands release, security, and compatibility responsibilities.
- Can merge, manage releases, and represent the project.
- Is approved by existing maintainers; the current owner makes the final call.

## Good first issues

A good first issue should have a clear user-visible outcome, a known relevant
module, explicit validation steps, and no hidden production dependency.
Maintainers should label these `good first issue` and provide a starting point.
